# 沉船楼层入口、出口与楼层清空状态 设计（短）

- 日期：2026-10-28
- 规模：小改动（1 个数据字段 + 1 个场景 + 生成器 + 重置逻辑）

## 意图

现在沉船每层只有一个看得见的下楼梯子，入口不可见、没有上楼，玩家不知道自己从哪儿进来、也不知道哪儿能出去。本次给每层补上可见的入口与出口、加上楼、并在清空本层后提示出口。

## 已定方案

- **入口**：`DungeonFloor.entry` 坐标改为写入新的 `DUNGEON_TILE.exit` 瓦片，画成木舱口。
  - 第 1 层：靠近提示「离开沉船」，回到岛上的破船旁。
  - 第 2/3 层：靠近提示「上一层」，回到上一层。
- **出口**：现有 `stairs` 瓦片保留，画成向下的木梯并加亮描边；靠近提示「下一层」；第 3 层的楼梯直接「离开沉船」。
- **出口指示**：进入楼层后，屏幕边缘画一个指向出口的小箭头；出口进入视野后箭头隐藏。
- **清空本层**：本层敌人全部倒下时，横幅「本层已清空」，出口上方出现一道光柱。
- **保持清空**：`dungeon.clearedFloors: number[]` 记录本次已清空的楼层；重新进入该层不再生成敌人，光柱仍在。每周一 06:00 重置（与开箱记录同步），离开副本时的延迟重置同样清空。

## 约束

- 存档版本仍为 v4；`clearedFloors` 缺失时按 `[]` 补齐，不升级版本。
- 纯逻辑（清空标记、重置、可通行瓦片）放 `systems/` 与 `world/dungeonGen.ts`，场景只做绘制与交互。
- 现有 276 项测试、`typecheck`/`lint`/`build` 必须保持通过。

## 测试要点

- 生成器：每层 `entry` 瓦片是 `exit`，且 `isDungeonWalkable` 认可它。
- `markFloorCleared` / `isFloorCleared`：写入、查询、幂等。
- 周重置与离开副本的延迟重置都会清空 `clearedFloors`。
- 存档：缺少 `clearedFloors` 的 v4 存档读入后为 `[]`。
